# Довод

Трекер задач внутри Telegram. Бот читает рабочие чаты и чат поддержки, находит
новые запросы и продолжения старых, а человек одной кнопкой превращает их в
задачи с ответственным, сроком и критерием готовности. Руководитель получает
утреннюю сводку и эскалации, когда обещание клиенту нарушено.

## Как устроено

Три процесса над одной базой:

| Процесс | Команда | Что делает |
|---|---|---|
| API и мини-апп | `uvicorn app.main:app --port 8010` | HTTP для мини-аппа, раздаёт собранный фронт |
| Бот | `python -m app.bot.telegram` | `/start`, `/digest`, `/id`, кнопка мини-аппа |
| Воркер | `python -m app.worker` | чтение чатов, разбор моделью, эскалации, сводка в 09:00 |

Два подключения к Telegram — намеренно:

- **Telethon (ваш аккаунт)** только читает. Он видит все чаты, где вы есть,
  включая группы без бота. Отправка через него заблокирована в коде: иначе
  система писала бы клиентам от имени живого человека.
- **Бот** только пишет: сводку, эскалации, кнопку мини-аппа.

Правила, на которых всё держится, — в `backend/app/service.py`:
«Готово» ставит только автор задачи; заявку без ответа клиенту закрыть нельзя
(правило включается руководителем); отмена задачи возвращает сообщения в
разбор, а не удаляет их.

## Запуск на пилоте

Команды для PowerShell, из папки `dovod`.

1. **Бот.** Создайте бота у [@BotFather](https://t.me/BotFather), токен — в `.env`:

   ```powershell
   Copy-Item .env.example .env
   ```

   Заполните `BOT_TOKEN`. Без него вход в мини-апп невозможен: им проверяется подпись Telegram.

2. **Зависимости.**

   ```powershell
   cd backend; pip install -r requirements.txt; cd ..\miniapp; npm install; npm run build; cd ..
   ```

3. **Ваш Telegram ID.** Запустите бота, напишите ему `/id`, впишите число в `MANAGER_TG_USER_ID`.

   ```powershell
   cd backend; python -m app.bot.telegram
   ```

4. **База.** Руководитель и правила эскалации; `--demo` добавит примеры отелей и задач,
   чтобы первое открытие не было пустым.

   ```powershell
   python -m app.seed --demo
   ```

5. **HTTPS-адрес.** Telegram открывает мини-апп только по HTTPS. Для пилота — туннель:

   ```powershell
   cloudflared tunnel --url http://localhost:8010
   ```

   Адрес вида `https://….trycloudflare.com` — в `MINIAPP_URL`, перезапустите бота:
   у него в меню появится кнопка «Довод».

6. **Чтение чатов.** Получите `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` на
   [my.telegram.org](https://my.telegram.org) → API development tools, затем один раз:

   ```powershell
   python -m app.ingest.login
   ```

   Файл сессии — полный доступ к аккаунту: не коммитьте и не пересылайте его.
   Новые чаты регистрируются **выключенными** — включает их руководитель.
   После первого запуска воркера (шаг 7) посмотрите список и включите нужные:

   ```powershell
   python -m app.chats
   python -m app.chats on 1
   python -m app.chats on all      # все групповые, с текущего момента
   ```

   `on all` не включает личные переписки (только по одной, с `--consent`) и
   не берёт историю: иначе сотни чатов разом встали бы в очередь разбора
   перед свежими обращениями. Нужна история — добавьте `--history`.

7. **Разбор.** `ANTHROPIC_API_KEY` в `.env`, затем воркер:

   ```powershell
   python -m app.worker
   ```

Проверить, что всё подключено: `http://localhost:8010/health` — в поле `degraded` перечислено, чего не хватает.

```powershell
cd backend
python tests/test_auth.py      # подпись Telegram: подделка, чужой токен, просрочка
python tests/test_service.py   # правила: приёмка, SLA, экономика, сводка

```

## Что ещё не сделано

Честный список, чтобы пилот не упёрся в него неожиданно.

- **Разбор не проверен на живой модели.** Промпт, схема и запись результатов
  проверены офлайн; качество классификации на ваших чатах покажет только пилот.
- **Экранов «Источники» и «Правила» нет в мини-аппе.** API готово
  (`/api/chats`, `/api/rules`); чаты пока включаются командой `python -m app.chats`.
- **Исполнителю не приходит уведомление** о новой задаче — только руководителю
  приходят сводка и эскалации.
- **Скриншоты не читаются.** Картинка без подписи отсеивается с пометкой об этом.
- **Эскалации — три правила из пяти**, показанных в прототипе: первый ответ,
  задача без движения, третье обращение отеля. «Возврат с проверки» ждёт учёта возвратов.
- **Номер задачи** считается по количеству задач: при одновременном создании
  двумя людьми возможен конфликт. На пилоте из трёх человек это не проявится.
- **Миграций нет** — схема создаётся при старте. Если модель данных меняется,
  пилотную базу проще пересоздать.
